# 管理员权限说明

管理员登录身份仍为 `super_admin` 或 `admin`，普通用户为 `user`。管理员账号额外使用管理员类型、数据范围和权限清单决定可用功能。

## 预设类型

| 类型 | 默认能力 | 默认范围 |
| --- | --- | --- |
| 超级管理员 | 全部能力，包括管理员账号管理 | 全局 |
| 普通管理员 | 全部业务能力，不含管理员账号管理 | 全局 |
| 用户管理员 | 部门、用户、API Key、配额、用量与内容 | 授权部门及子部门 |
| RAG 管理员 | RAG 知识库、数据集、上传、向量化与评测 | 授权部门及子部门 |
| API 管理员 | 厂商、模型、价格、API Key、配额与用量 | 全局 |
| 自定义管理员 | 仅勾选的能力 | 可选全局或授权部门 |

在“管理员管理”中选择权限会切换为自定义权限模式，并以勾选结果覆盖预设。修改类型但不勾选权限时恢复该类型的预设权限。后台的“权限配置”独立页面集中展示预设、权限点与管理员当前有效权限，并可直接更新管理员的类型、数据范围、授权部门和单独权限。

## 安全边界

- 只有超级管理员拥有 `admins.manage`，因此只有超级管理员可以创建、修改、重置密码或撤销管理员账号会话。
- 非超级管理员不会获得影响超级管理员账号的入口。
- 菜单隐藏仅改善体验；每个受保护的 `/admin-api/*` 请求都会在会话认证后执行服务端能力校验。未知的受保护路由默认拒绝。
- 数据范围与功能权限同时生效。选择“授权部门及子部门”时，原有 `managed_department_ids` 继续限制可见和可操作的数据。
- 权限、类型或数据范围发生变化后，系统会撤销目标管理员的现有登录会话，要求重新登录。
