# TokenHub 后台信息架构、WAF 独立菜单与 Web 能力补齐设计

**日期：** 2026-07-10  
**状态：** 已确认设计，待实施计划审批  
**范围：** Admin Web、受权限保护的 Admin API 与必要服务层；不修改环境、Docker Compose、Caddyfile 或外部普通用户登录模型。

## 1. 目标

将 Admin Web 从“资源表逐项堆在侧栏”的导航方式调整为“业务域一级入口 + 页面二级页签”。WAF 防火墙成为独立一级菜单，规则、入口防护、发布版本、攻击事件、IP 封禁和 WAF 告警在同一页面收口。

同时补齐已存在的后端能力但 Web 尚无入口的操作面，并为确实缺少的管理能力补充受控 API 与页面。普通用户仍只通过 API 密钥访问外部能力，不创建普通用户 Web 登录或自助门户。

## 2. 信息架构

侧栏只展示下列一级业务域；进入每个业务域后，以可刷新的二级页签组织功能。

| 一级菜单 | 二级页签 |
| --- | --- |
| 运营中心 | 数据总览、会话测试、大屏分享、访问记录 |
| 组织与权限 | 部门管理、普通用户、管理员账号 |
| 模型服务 | 厂商管理、模型管理、价格配置 |
| API 接入 | API 密钥、模型限额、限额策略、限额绑定 |
| 用量中心 | 用量明细、多模态任务、媒体资产、内容留存、会话归档、导出任务 |
| RAG 知识库 | 总览、知识库、导入审核、图片与向量、反馈纠偏、检索评估、高级数据、RAG 设置 |
| WAF 防火墙 | WAF 总览、入口防护、规则管理、发布与版本、攻击事件、IP 封禁、WAF 告警 |
| 安全审计 | 脱敏策略、脱敏事件、告警中心、日志中心、审计日志 |
| 系统运维 | 运行状态、证书与入口、基础设置、留存与清理、日志归档、通用告警、高级设置 |

### 2.1 归属调整

- 当前安全菜单中的 WAF 规则、发布版本和攻击事件移入 WAF 防火墙。
- 当前系统设置中的 `firewall_settings` 移入 WAF 的入口防护页签。
- 当前通用告警中的 WAF 突增阈值移入 WAF 告警；厂商错误率、队列积压和证书阈值保留在系统运维的通用告警。
- 管理员账号从系统设置移入组织与权限。
- RAG 的审核、图片包、AI 图片处理与向量监控设置移入 RAG 设置页签。
- 日志留存策略与归档文件移入系统运维；业务日志、告警和审计记录保留在安全审计。

## 3. Web 能力补齐

### 3.1 已有 API 或服务，只需补前端入口

| 能力 | 目标页面 | 实施方式 |
| --- | --- | --- |
| Admin 健康检查 | 系统运维 / 运行状态 | 使用现有 `/admin-api/health` 展示 PHP、MySQL、Redis 健康度 |
| 导出文件下载 | 用量中心 / 导出任务 | 成功任务调用现有 `/admin-api/exports/{export_id}/download-url`，跳转短效下载地址 |
| WAF 模板带入 | WAF / 规则管理 | 使用现有模板接口，把选中模板转换为新建规则表单的预填值 |
| WAF 设置与告警迁移 | WAF / 入口防护、WAF 告警 | 复用现有 settings-center 的字段读写，不复制设置存储 |

### 3.2 需要新增 Admin API 与 Web 页面

| 能力 | 页面 | 后端职责 |
| --- | --- | --- |
| WAF 总览 | WAF / WAF 总览 | 汇总当前发布版本、规则状态、命中统计、最近事件、IP 封禁数量、导入/自动处置状态 |
| IP 封禁管理 | WAF / IP 封禁 | 查询 `system_ip_bans`，支持人工封禁、解封和审计 |
| 告警生命周期 | 安全审计 / 告警中心 | 对 `open`、`acknowledged`、`resolved` 提供确认、关闭与处理备注，写审计记录 |
| 运维状态 | 系统运维 / 运行状态 | 汇总 Redis 队列、失败队列、最近任务结果与健康状态；只读展示 |
| 媒体资产下载 | 用量中心 / 媒体资产 | 为管理员生成带权限范围的短效下载令牌 |
| 日志归档下载 | 系统运维 / 日志归档 | 为管理员生成带权限范围的短效下载令牌，不暴露真实文件路径 |

## 4. 路由、权限与数据流

### 4.1 前端导航

新增业务域导航配置，取代当前按资源逐项在侧栏展开的定义。每个页签仍映射到一个现有资源页或定制渲染器，并根据角色在渲染前过滤。

页面状态写入 hash，例如 `#/waf/events`、`#/operations/health`。刷新、复制链接和浏览器前进后退均应恢复对应业务域和页签。

### 4.2 服务端权限

WAF、系统 IP 封禁、运维状态、日志归档下载和告警处置均要求服务端 `super_admin` 授权。不得只隐藏前端页签：现有 WAF 路由只使用管理员认证中间件，实施时必须补足服务端角色校验。

部门管理员保留已有部门范围的数据读取权限；普通用户不获得新的后台能力。所有下载令牌必须在生成和消费阶段二次检查管理员身份及部门范围。

### 4.3 IP 封禁状态

人工封禁或解封应更新 `system_ip_bans`、刷新 Redis 封禁缓存并写审计记录。页面必须区分：

- 应用层系统封禁：写入后立即由全局 IP 封禁中间件生效；
- Caddy 边缘封禁：需要 WAF fragment 已成功发布，或已启用保存后自动发布。

页面展示当前边缘发布状态，不能将“数据库记录已写入”表述成“Caddy 已生效”。

### 4.4 安全下载

导出任务沿用现有安全下载令牌。媒体和日志归档增加管理员专用令牌载荷，包含目标对象、管理员身份、授权范围和过期时间。下载控制器在读取文件前验证令牌、对象存在性、范围和过期状态；错误响应不返回真实路径。

## 5. 不纳入 Web 的能力

以下能力保留为部署或运维流程，不提供后台一键执行：数据库迁移、备份恢复、队列进程启停、Caddy 原始脚本执行、压力测试、验收脚本与环境变更。后台仅显示健康度、队列和审计信息。

外部 API 的模型、额度、文件、同步、Webhook 与 RAG 调用仍面向 API 密钥客户端，不增加普通用户 Web 登录。

## 6. 错误处理与审计

- WAF 发布保留现有预览、Dry Run、高危确认和发布结果反馈。
- IP 封禁、告警处置和下载链接生成失败时，页面保留当前列表状态并显示接口返回的可读错误。
- 无权限、过期令牌和范围不匹配分别返回安全的 403/404，不泄漏文件路径、令牌或跨部门数据。
- 人工封禁、解封、告警确认/关闭、WAF 发布/回滚、媒体/归档下载均写入审计日志。

## 7. 验收与测试

1. 一级菜单和页签按角色正确过滤，hash 深链可恢复页面状态。
2. 超级管理员以外的账户访问新增 WAF/运维管理接口得到 403。
3. IP 封禁的创建、列表、解封、Redis 缓存刷新、WAF 发布状态和审计记录均可验证。
4. WAF 模板可预填规则；预览、Dry Run、发布、回滚和事件处置不回归。
5. 告警可在 `open → acknowledged → resolved` 间受控流转并记录操作人和备注。
6. 导出、媒体与日志归档下载仅对授权管理员生成短效 URL；跨范围、过期和缺失对象均被拒绝。
7. 运行状态正确聚合健康度与队列摘要，但不暴露一键执行高风险运维动作。
8. 新增聚焦服务/控制器/前端契约测试，并在 Docker PHP 环境执行完整回归。

## 8. 非目标

- 不改动 `.env`、Docker Compose、Caddyfile 或部署拓扑。
- 不添加普通用户 Web 登录。
- 不将迁移、备份恢复或进程控制暴露为后台按钮。
- 不改变既有 WAF 规则格式、发布/回滚语义或外部 API 契约，除非新增 Admin API 所需。
