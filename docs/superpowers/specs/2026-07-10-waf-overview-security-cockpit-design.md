# WAF 总览安全驾驶舱设计

## 目标

将管理端 `#/waf/waf-overview` 从原始 API 对象展示，重构为同时服务安全运营人员和管理者的 WAF 安全驾驶舱。页面应让用户快速理解：WAF 是否处于可用防护状态、正在防护什么、近期拦截了什么、以及应从哪里进入下一步处置。

## 范围与约束

- 仅调整 `waf-overview` 的前端渲染、样式和前端契约测试。
- 继续使用既有 `GET /admin-api/waf/overview` 响应，不改变 `WafService::overview()`、发布、封禁、规则或攻击记录的后端契约。
- 快捷入口只跳转到既有的规则、攻击记录和 IP 封禁页面；总览页不新增直接发布、封禁或删除等高风险动作。
- 保持桌面端驾驶舱布局与移动端单列可用性。

## 页面结构

### 1. WAF 防护态势

页面首屏展示当前版本和发布状态，并将机器状态转换为业务语义：

- `published`：边缘防护已发布。
- `unpublished`：边缘防护待发布，并提示当前变更尚未生效。
- 其他失败或未知状态：显示异常状态与风险提示。

四张指标卡展示：启用规则数、活跃封禁 IP、攻击事件总数和已拦截事件数。每张卡附简短说明，解释其与 WAF 防护能力的关系，而非只展示数字。

首屏提供“查看规则”“查看攻击记录”“管理 IP 封禁”三个快捷入口，分别进入现有页面。

### 2. 防护能力与威胁热点

防护能力区以清晰、简短的说明呈现现有 WAF 能力：规则匹配拦截、敏感路径保护、异常来源 IP 封禁、攻击事件留痕与审计。该区域帮助非安全专业用户理解系统已经覆盖的防护链路。

威胁热点区根据 `top_rules` 展示风险规则排行，包含规则名称、命中次数与相对占比的进度条。没有数据时使用“当前统计窗口内未发现攻击命中”的安全空态，而不是空白卡片。

### 3. 近期攻击与处置闭环

近期攻击区展示最多五条 `recent_events`：时间、来源 IP、访问路径、触发规则、拦截或观察状态，以及已有的处置状态。提供“查看全部攻击记录”入口。

当存在活跃封禁或未处置阻断事件时，页面显示待办提示，指向攻击记录处理或 IP 封禁管理；总览只提示与导航，避免将高风险操作放入汇总页面。

状态使用中文业务语义和清晰颜色：已拦截、观察中、待发布、异常、暂无风险。不得直接向用户展示未解释的数据库字段值或整个 JSON 对象。

## 数据流、错误处理与可访问性

页面加载时请求一次 `/admin-api/waf/overview`，将返回数据分组为发布态势、指标、规则热点与近期攻击后渲染。快捷操作采用既有哈希路由。

无攻击数据时保留安全空态。接口加载失败时展示可理解的失败文案与重试按钮，不渲染半截数据。所有状态不能仅以颜色区分，须同时提供文字；小屏幕使用单列布局，保留告警与全部快捷入口。

## 测试与验收

先写前端契约测试，确认总览：

1. 不再把接口结果直接交给 `renderDataDetails`。
2. 渲染防护态势、四项核心指标、防护能力、规则热点与近期攻击。
3. 包含无攻击空态与接口失败重试路径。
4. 提供规则、攻击记录和 IP 封禁三个既有入口。

随后以最小实现满足测试，并在 Docker PHP 环境中运行聚焦前端测试；页面可访问时再进行实际浏览器检查，确认桌面和窄屏布局、空态与失败态。

## 非目标

- 不新增统计口径或后端接口。
- 不修改 Caddy、Docker Compose、环境变量或 WAF 生成规则。
- 不在总览页增加发布、封禁、解封等破坏性动作。
