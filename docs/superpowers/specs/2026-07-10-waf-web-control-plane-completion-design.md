# WAF Web 控制面补全设计

## 目标

将 TokenHub 已存在的 WAF 后端能力完整接入管理端 Web，形成“配置规则—预检—发布—观察—处置—版本回退”的闭环。本轮不新增日志导入健康状态、封禁有效期等后端数据模型，不修改 Caddy、Docker Compose 或环境配置。

## 当前缺口

- 发布版本使用通用 CRUD 列表，专用 `/admin-api/waf/versions` 未被页面消费。
- 版本差异以原始对象展示，回滚没有专用风险说明和二次确认。
- 规则创建和编辑要求手写 Matcher JSON，保存前不能针对当前规则预检。
- 事件处置使用固定备注，后端支持的 `note` 没有暴露给管理员。
- 自动处置参数固定为 10 次、5 分钟，没有读取现有告警设置或允许本次调整。
- 总览把 `disposition_status = open` 排除在待处置统计之外。

## 范围

### 1. 引导式规则编辑与单条预检

规则页继续通过既有 `/admin-api/waf-rules` CRUD 保存数据，但新增 WAF 专用创建/编辑器。编辑器包含规则编码、作用域、动作、优先级、状态、说明和 Matcher 类型。

Matcher 类型按 `WafService` 已支持的结构呈现：

- IP：生效路径、允许 CIDR、拒绝 CIDR。
- 路径：路径或通配模式列表。
- 方法：拒绝的 HTTP 方法列表。
- 查询参数：敏感参数名与匹配表达式列表。
- 请求头：请求头名称或“名称: 值”规则。
- 请求体大小：最大字节数。
- 安全响应头：响应头“名称: 值”规则。

编辑现有规则时，将 Matcher JSON 解码并回填到对应字段；保存时再转换为后端当前结构。表单保留高级 JSON 预览，便于管理员核对最终 Matcher，但不要求手写 JSON。

“预检当前规则”调用既有 `POST /admin-api/waf/preview`，请求体为 `{ rules: [candidate] }`。校验错误直接映射到字段和中文说明；高危项显示风险原因与醒目标识；预检未通过时不允许保存。模板仍使用相同编辑器预填。

### 2. 专用版本管理页面

`waf-rule-versions` 改用专用渲染器，并通过 `GET /admin-api/waf/versions` 加载数据。页面展示当前发布版本、历史版本、发布状态、发布人和时间。

“查看差异”调用现有版本 diff 接口，将 `rules` 与 `caddyfile_fragment` 的行差异分区展示，使用新增、删除、上下文三种视觉状态，不再展示原始对象。

“回滚到此版本”只对非当前发布版本出现。点击后展示目标版本、当前版本和影响说明，并要求二次确认；确认后调用现有回滚接口。结果明确显示验证、重载和发布状态，失败时保留后端错误信息但不暴露敏感配置。

“发布当前规则”沿用规则页的 Dry Run 与高危确认流程，避免通用资源动作绕过确认。

### 3. 事件处置与自动处置

攻击记录的“已复核、误报、封禁 IP、解封 IP”改为处置弹窗。弹窗展示事件摘要和动作影响，允许输入必填处置说明，并将说明传给现有 `note` 字段。封禁与解封动作需要额外确认。

自动处置改为配置弹窗。默认阈值和窗口从 `/admin-api/system/settings-center` 的 `alert_thresholds.waf_spike_count` 与 `waf_spike_window_minutes` 读取，管理员可为本次执行调整。提交前显示“将扫描指定窗口内重复阻断来源并执行系统级封禁”的影响说明，执行结果使用结构化摘要展示封禁数量与来源 IP。

### 4. 总览闭环

总览将 `disposition_status` 缺失或值为 `open` 的阻断事件计为待处置。快捷入口增加“版本管理”；存在待处置事件时继续引导至攻击记录，不在总览直接执行高风险操作。

## 数据流与安全边界

- 所有写操作继续使用现有管理员认证和 CSRF 机制。
- 规则保存、发布、回滚、事件处置和自动封禁均不新增后端路由。
- 规则预检只验证候选规则，不写数据库、不发布 Caddy 片段。
- 回滚、封禁、解封必须在动作当下确认；普通查看、筛选和预检不需要确认。
- 页面不得展示完整 `rules_snapshot`、未脱敏日志或无说明的原始 JSON 对象。

## 错误处理

- 列表加载失败时显示错误和重试按钮，不用伪造数据行代替错误状态。
- 规则字段解析失败时保留用户输入，并在对应字段附近显示原因。
- 预检错误和高危提示分区展示；后端返回 `requires_confirmation` 时不得误报发布成功。
- 回滚或发布失败时显示验证失败、重载失败或未知失败，不刷新掉失败结果。
- 事件处置完成后刷新当前筛选结果；失败时保留弹窗内容和管理员填写的备注。

## 测试与验收

采用测试先行：

1. 扩展 `AdminWafControlPlaneFrontendTest.php`，先锁定专用版本页、引导式 Matcher、单条预检、处置备注、参数化自动处置和 `open` 待处置统计。
2. 扩展 WAF 服务/控制器契约测试，确认页面使用现有专用版本与 diff 接口，不新增路由。
3. 运行 `node --check public/admin/assets/js/table.js`。
4. 在 Docker PHP 中运行 WAF 聚焦前端测试、`WafServiceTest.php`、`LoginIpBanServiceTest.php` 与相关管理端导航测试。
5. 在已登录管理端验证规则创建/编辑、版本 diff、回滚确认、事件备注、自动处置参数和窄屏布局。

## 非目标

- 不新增 WAF 日志导入状态 API。
- 不增加封禁到期时间或数据库迁移。
- 不改变事件导入 Worker、Caddy 片段生成、系统级 IP 拒绝或现有设置契约。
- 不修复与 WAF 无关的管理端主题切换历史契约问题。
