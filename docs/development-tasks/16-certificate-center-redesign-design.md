# 16. 证书中心重构设计

## 目标

重写管理后台的“证书与入口”页面，使管理员可以在一个连续流程中完成证书申请、验证、部署、续签观察和告警处置。页面不再把“申请证书、证书配置、真实状态、告警检查”拆成四个无上下文关联的标签页。

成功的定义是：证书已签发或由内部 CA 签出、已被 Caddy 加载、并且真实证书扫描接口能够读到该证书。仅保存设置、生成 Caddy 片段或返回 HTTP 202 不能显示为“申请成功”。

## 固定的证书类型

| 类型 | 目标 | 签发方式 | 验证与续签 |
| --- | --- | --- | --- |
| 域名证书 | 公网 DNS 名称 | ACME / Let’s Encrypt | HTTP-01 或 TLS-ALPN-01；由 Caddy 管理续签 |
| 公网 IP 证书 | 外网可访问 IPv4 或 IPv6 | Let’s Encrypt IP 短期证书 | HTTP-01 或 TLS-ALPN-01；6 天证书，每 12 小时检查并续签 |
| 内网 IP 证书 | RFC1918/受控网络 IP | Caddy 内部 CA | 不请求公网 CA；自动签发与续签，并展示根证书信任指引 |

公网 IP 证书必须校验为公网地址，并在提交前检查验证端口是否可达。内网 IP 不得落入 Let’s Encrypt 分支。域名证书与公网 IP 证书都不能在未完成验证和部署时标记成功。

内网 IP 申请一次只能选择一个 IP，并生成一张仅包含该 IP SAN 的内部 CA 叶证书。页面先加载服务器发现的内网 IP 列表，管理员必须单选；当列表为空或目标未被发现时允许手工输入一个 IP。后端拒绝多 IP 输入，避免将多个目标合并到同一张证书或在用户无感知的情况下批量签发。

## 页面信息架构

页面名称统一为“证书中心”。首屏由四个运行态摘要组成：当前安全状态、即将到期、自动续签覆盖率、待处理申请/错误。

摘要下方为“申请或更换证书”卡片：三张可选类型卡展示签发来源、有效期/续签策略和使用范围；选中类型后仅显示该类型的目标字段和前置条件。请求表单与类型卡保持在同一位置，避免跳页或隐藏在二级 Tab 中。

申请提交后，右侧或窄屏下方显示当前操作进度：`配置已保存 -> 前置检查 -> CA 验证/内部签发 -> Caddy 部署 -> 真实证书回读`。操作只有处于最后一步且回读匹配目标后才显示成功。

页面下半部分依次展示受管证书清单、单张证书的续签/操作记录、告警与“立即检查”操作。清单中的公网 IP 条目显示距离下次续签检查的时间和短期证书剩余小时数；内网 IP 条目提供根证书信任说明入口。

## 后端与数据流

### 操作记录

新增持久化的证书操作记录，至少保存：操作 ID、类型、目标、状态、当前阶段、错误码/安全错误摘要、创建/更新时间、签发文件路径、真实证书指纹与到期时间。状态为 `queued`、`preflight_failed`、`validating`、`issuing`、`deploying`、`verified` 或 `failed`。

`POST /admin-api/system/certificate-request` 继续作为创建入口，但返回操作 ID 和初始状态，不再把“已提交”解释成成功。新增只读操作详情接口供页面轮询，直到 `verified`、`failed` 或超时。操作详情不返回私钥、完整执行命令或敏感路径。

### 签发适配器

`CertificateRequestService` 只负责归一化、类型选择和创建操作。将签发与部署抽到独立适配器：

- `DomainCertificateIssuer` 写入受管域名目标，复用 Caddy 的 ACME 能力。
- `PublicIpCertificateIssuer` 调用部署环境提供的 Certbot 5.4+（或等价兼容客户端）请求 Let’s Encrypt `shortlived` profile 的 IP SAN 证书，并记录证书/私钥的受控存放路径。
- `InternalIpCertificateIssuer` 写入 `tls internal` 片段，使用 Caddy 内部 CA。

所有适配器使用同一“写候选片段 -> Caddy 校验 -> 原子替换 -> 重新加载 -> 真实证书扫描”的部署器。该部署器复用 WAF 服务已有的回滚模式：校验或重载失败时恢复上一片段并将操作置为 `failed`。

### 续签与状态

队列 worker 增加证书维护任务：公网 IP 证书每 12 小时检查，进入续签窗口时调用签发适配器；域名与内网 IP 只做真实状态检查和异常告警，避免与 Caddy 自己的管理机制竞争。每次完成后都扫描证书文件、解析 SAN/签发者/到期时间，并更新最近操作记录。

告警直接依据真实扫描结果和操作失败结果生成。公网 IP 在剩余 48 小时内仍未成功续签为高优先级；证书已过期或 Caddy 重载失败为严重告警。

## 前置条件与失败处理

公网 IP 申请前必须通过以下检查：目标为公网 IP、服务端可执行已配置的 ACME 客户端、80 或 443 按选定挑战方式可访问、Caddy 配置能够读取受管证书路径。若其中任一检查失败，页面显示可执行的原因和修复提示，不创建“成功”记录。

本次不改 `.env`、Docker Compose 或 Caddyfile。现有 Caddyfile 已导入 TLS 片段；生产部署需由运维提供 Certbot 可执行环境、受控证书目录和用于校验/重载 Caddy 的既有命令。应用将明确报告这些前置条件缺失，而不是伪造签发成功。

## 测试与验收

测试先行覆盖：

1. 三种类型各自的目标校验、签发来源和 Caddy 片段；公网 IP 不可接受私网地址，内网 IP 不可进入公网 CA。
2. 公网 IP 的前置检查、短期 profile 请求参数、续签计划、失败回滚和审计记录。
3. Caddy 校验/重载失败时恢复旧片段，且操作不会进入 `verified`。
4. 真实证书扫描的 SAN、类型、到期时间与操作目标匹配；不匹配时显示失败。
5. 管理端前端存在三个类型选择、进度状态、续签/到期状态和真实状态表；只有 `verified` 文案可表示申请完成。
6. 聚焦 PHP 服务测试、前端静态契约测试，以及 Docker PHP 环境中的相关测试。真实 Let’s Encrypt 申请仅使用 staging 端点进行受控人工验收，避免触发生产限额。

验收时分别完成域名、可公网访问 IP、内网 IP 三条流程；每条都要验证最终 Caddy 加载的证书与状态接口读到的证书一致。公网 IP 还需验证维护任务已登记并在模拟的续签窗口中成功运行。

## 非目标

不新增普通用户登录入口，不暴露证书私钥或管理命令，不改变系统设置中心的既有路由契约，也不在此任务中改动部署环境文件。

## 实施验证（2026-07-10）

- 已通过 Docker PHP 的证书请求、系统设置、真实证书状态、证书中心前端和管理员安全契约测试。
- 内网 IP 申请现在只接受一个目标；证书中心从服务器候选 IP 中提供单选，并在候选为空时提供单个手工输入。针对 `172.18.0.6` 的临时 Caddy 内部 CA 运行已生成本地签发的 IP SAN 证书。
- 当前运行容器具备 Caddy 2.11.4，但未安装 Certbot，且未配置 `TOKENHUB_PUBLIC_IP_CERTBOT_COMMAND`。公网 IP 申请因此会返回明确的前置条件错误，不会保存为已成功签发或已部署。
- 真实 Let’s Encrypt 公网 IP 签发和 12 小时续签验收需要在获准调整部署环境后，安装兼容 short-lived profile 的 Certbot、配置挑战端口和受控 Caddy 重载命令，再使用 staging 端点完成。
